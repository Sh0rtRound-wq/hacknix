This document explains every file, folder, and system in this flake in depth.
The goal is that after reading this you understand exactly what everything does,
why it exists, and how all the pieces connect together.

 PHILOSOPHY
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

This flake is designed to be fully portable. You should be able to clone it onto
any machine, run load_info.sh, run nixos-rebuild switch, and have a fully working
system with the complete rice intact. No manual setup beyond that.

There are two layers of configuration:

  DECLARATIVE (in the flake, same on every device)
    Everything that should be consistent no matter what machine you are on.
    The rice, the packages, the services, the keybinds, the themes. If you
    change something here and rebuild, it changes on that device and every
    other device next time they rebuild.

  DEVICE STATE (in ~/.config/hypr/settings.json, per-machine)
    Everything that is specific to one machine. Monitor layout, resolution,
    refresh rate. These persist across rebuilds on the same machine but are
    NOT shared between machines. On first install they get sensible defaults
    from the activation hook so the rice works immediately, and you only need
    to touch them if you want to change something like monitor resolution.

The separation is intentional. Your rice looks and behaves the same everywhere.
Your monitor config is different per device because displays are different.

 flake.nix
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

The entry point for the entire system. Nix reads this first.

INPUTS
  Three external dependencies are declared here:

  nixpkgs (pinned to a specific commit)
    The main package set. Everything installed on the system comes from here.
    It is pinned to a specific commit hash rather than a branch so that the
    system is reproducible. Every machine running this flake gets the exact
    same versions of every package.

  home-manager (follows nixpkgs)
    The tool that manages user-level configuration. It handles deploying config
    files, setting up programs, and running activation hooks when you rebuild.
    "follows nixpkgs" means it uses the same nixpkgs as the system rather than
    pulling in its own version, keeping everything consistent.

  nixpkgs-neo4j (pinned to nixos-22.11)
    A separate older nixpkgs snapshot used only to get a specific version of
    neo4j that is not available in the current nixpkgs. Only used by the
    pentest profile. Everything else uses the main nixpkgs.

MKHOST FUNCTION
  Instead of writing each system configuration from scratch, a helper function
  called mkHost is defined. It takes a hostname, a profile, a username, and a
  wallpaper directory, and constructs a full NixOS system configuration.

  This is what makes the flake portable. Hardware values from config.nix
  (gpu, cpuVendor, inputSensitivity, etc.) are read once and passed into
  both the system config (base.nix) and the user config (user.nix) as
  specialArgs. This means any file in the flake can reference those values
  without having to re-read config.nix itself.

  The wallpaperDir is always set to ~/hacknix/wallpapers. This means wallpapers
  ship with the flake and are available immediately on any device.

NIXOSCONFIGURATIONS
  Two system configurations are defined:

  pentest
    Uses profiles/pentest.nix for the extra package set.
    Inherits hostname and user from config.nix.

  gaming
    Uses profiles/gaming.nix for the extra package set.
    Inherits hostname and user from config.nix.

  Both share base.nix and user.nix entirely. The only difference between them
  is the profile. To switch between them you change which name you pass to
  nixos-rebuild switch, for example:
    sudo nixos-rebuild switch --flake .#gaming
    sudo nixos-rebuild switch --flake .#pentest

 config.nix
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

The only file you manually edit when setting up on a new machine. It contains
every value that differs between physical devices.

  hostname
    The machine's network hostname. Used by base.nix for networking.hostName
    and also used by NixOS to identify which system configuration to apply.

  user
    Your Linux username. Home-manager deploys all user config under this name.
    Also controls which user gets auto-login.

  powerProfile
    Controls the system power governor. Three options:
      "performance"  — cpu runs at max clock speed always
      "balanced"     — schedutil governor, scales with demand (default)
      "power-saver"  — cpufreq powersave, lowest clocks, best battery life
    On a laptop you probably want "balanced". On a desktop "performance".
    This also triggers a udev rule that re-locks the profile when AC power
    is plugged or unplugged, so it does not drift.

  cpuVendor
    Either "amd" or "intel". Controls microcode updates and kernel params.
    AMD gets amd_pstate=active for better power management.
    Intel gets default scheduler behavior.

  gpu
    Controls which GPU driver and configuration to apply. Options:
      "amd"                 — AMD GPU only, uses open source amdgpu driver
      "intel"               — Intel integrated graphics only
      "nvidia"              — Dedicated NVIDIA GPU only
      "prime-nvidia-amd"    — Laptop with both NVIDIA and AMD (PRIME sync)
      "prime-nvidia-intel"  — Laptop with both NVIDIA and Intel (PRIME sync)
    PRIME modes enable NVIDIA PRIME sync so both GPUs work together correctly.

  nvidiaBusId / amdBusId / intelBusId
    Only relevant for prime modes. These are the PCI bus addresses of each GPU
    in the format NixOS expects (e.g. "PCI:1:0:0"). load_info.sh detects and
    fills these automatically. You should not need to set these by hand.

  inputSensitivity
    Mouse or touchpad sensitivity passed to Hyprland. Two sensible values:
      "-0.1"  — slight negative acceleration, good for a mouse
      "0.8"   — higher sensitivity, good for a laptop touchpad
    load_info.sh detects whether the device has a touchpad and sets this
    automatically. You can change it to any float that feels right to you.
    Changing this and rebuilding applies it immediately via the activation hook.

 load_info.sh
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

A bash script that auto-detects the hardware of whatever machine it runs on
and writes the correct config.nix values. Run this as your normal user (not
sudo) before the first nixos-rebuild switch on any new device.

What it detects and how:

  Hostname
    Reads from the system hostname command.

  CPU vendor
    Reads /proc/cpuinfo and checks for "AuthenticAMD". If found, amd.
    Otherwise defaults to intel.

  GPU mode
    Runs lspci and parses the output looking for display devices. Matches
    NVIDIA by name or vendor ID 10de, AMD/ATI by name or vendor ID 1002,
    Intel by name or vendor ID 8086. If both NVIDIA and AMD are found it
    sets prime-nvidia-amd. If both NVIDIA and Intel are found it sets
    prime-nvidia-intel. Single GPU gets its respective mode.

  PCI bus addresses
    For prime modes, extracts the PCI address from the lspci line and
    converts it from hex to the decimal format NixOS expects.

  Input device type
    Reads /proc/bus/input/devices and looks for the words touchpad, trackpad,
    or clickpad. If found, sets inputSensitivity to 0.8. Otherwise assumes
    mouse and sets -0.1.

After detecting everything it shows you a summary and asks for confirmation
before writing config.nix. After writing config.nix it also writes the
GPU-specific environment variables into ~/.config/hypr/settings.json so
Hyprland gets the right env vars for your GPU on first boot.

You only need to run this once per device. If you swap a GPU or other
hardware, run it again to update config.nix.

reinstall NixOS a new one gets generated. It is imported by base.nix.

 base.nix
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

The shared system-level configuration applied to every host. This is everything
that lives outside your home directory and is managed as root. Anything changed
here affects all devices on next rebuild.

BOOT
  Uses systemd-boot (EFI). Kernel is always linux_latest for newest hardware
  support. Boot parameters suppress all console noise for a clean boot:
  quiet, splash, loglevel=3, udev logging suppressed. NVIDIA devices get
  additional nvidia-drm.fbdev=1 for proper framebuffer support. AMD CPUs
  get amd_pstate=active for the modern active power management driver.

PLYMOUTH BOOT SPLASH
  A custom plymouth theme called "simple" is built inline from the files in
  rice/plymouth/simple/. It shows an animated splash screen during boot.
  The display manager is intentionally not used (Hyprland starts from the
  shell via UWSM), so the plymouth-quit-wait service is disabled to prevent
  a 60-second hang waiting for graphical.target which never fires in this setup.

KERNEL OPTIMIZATIONS
  TCP BBR congestion control is enabled with the fq qdisc for better network
  throughput. Socket buffer sizes are maximized (1GB). TCP fast open is
  enabled in both directions. vm.max_map_count is set to near max to support
  applications that need many memory mappings (games, VMs, JVM workloads).
  IRQ balancing is enabled to spread hardware interrupts across CPU cores.
  The r8168 module is loaded and r8169 is blacklisted for better Realtek NIC
  support. These are all set-and-forget performance improvements.

POWER MANAGEMENT
  The power governor is set from config.nix at boot via a oneshot systemd
  service called static-power-profile. A udev rule watches for AC adapter
  plug/unplug events and re-runs this service so the profile stays locked
  regardless of what other tools might try to change it.

HYPRLAND AND UWSM
  Hyprland is enabled at the system level (which installs it and sets up
  portals). UWSM (Universal Wayland Session Manager) is used to start
  Hyprland as a proper systemd session rather than launching it directly.
  This gives better integration with systemd services and prevents issues
  with services that need a running graphical session.
  Auto-login is configured so that on tty1 the user is logged in automatically
  and UWSM starts Hyprland without needing a display manager.

AUDIO
  PulseAudio is explicitly disabled. PipeWire handles all audio with both
  ALSA and PulseAudio compatibility layers enabled, so every application
  that expects either backend works correctly.

XDG PORTALS
  Both the Hyprland portal (for screen sharing, file picking in Wayland apps)
  and the GTK portal (for GTK app dialogs) are configured. xdgOpenUsePortal
  is enabled so xdg-open routes through the portal correctly in Wayland.

NETWORKING
  NetworkManager handles all network connections. The firewall is disabled
  (you manage security at the network level). Hostname comes from config.nix.
  The extraHosts section near the bottom is intentionally left with an empty
  block as a quick place to add /etc/hosts entries without touching the
  rest of the file.

SECURITY
  Polkit is enabled for privilege escalation dialogs in GUI apps.
  PAM u2f is configured for both login and sudo, so a hardware security
  key (YubiKey etc.) can be used for authentication.
  sudo is configured to preserve the HOME variable so home-manager paths
  work correctly when running sudo commands.

NVIDIA CONFIGURATION
  All NVIDIA settings are gated behind lib.mkIf isNvidia so they only
  apply on machines where config.nix has a GPU mode that includes nvidia.
  Modesetting is enabled, the open source kernel module is explicitly
  disabled (uses proprietary), power management is off to avoid suspend
  issues. PRIME sync is enabled for prime modes with the bus IDs from
  config.nix. The video driver for xserver is set even though xserver
  itself is disabled, because some NVIDIA tooling still reads it.

PACKAGES (system-wide)
  A large set of packages is installed at the system level so they are
  available to all users and in the initial shell before home-manager runs.
  This includes development tools (git, gcc, go, python3, nodejs, bun, ruby,
  php), system utilities (btop, fzf, tree, curl, wget), Wayland tools (grim,
  slurp, wl-clipboard, waybar, rofi, hyprlock, hypridle), media (mpv,
  obs-studio, vlc, ffmpeg), and productivity apps (obsidian, discord, anytype,
  taskwarrior3). Also includes docker, virtualbox, and wine for broader
  compatibility.

FONTS
  JetBrains Mono Nerd Font is the primary font used everywhere in the rice.
  Iosevka Nerd Font as a secondary option. Noto and Liberation for broad
  Unicode coverage. Hinting is set to slight and subpixel rendering to rgb
  for sharp text on LCD displays.

VIRTUALISATION
  libvirt and docker are both enabled. Your user is in the docker group
  so you can use docker without sudo.

NIX SETTINGS
  Flakes and the new nix command are enabled (required to use this flake).
  Garbage collection runs daily and removes generations older than 14 days
  to prevent the nix store from growing unboundedly. A registry entry
  is added under your username pointing to this flake, so you can reference
  it as a flake input from other flakes if needed.

KITTY TERMINAL
  Kitty configuration is deployed system-wide via environment.etc rather
  than in home-manager. It includes matugen color integration via an include
  directive pointing to /tmp/kitty-matugen-colors.conf which gets regenerated
  every time the wallpaper changes. Background is set to pure black so the
  terminal looks correct before the first wallpaper is loaded.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Thin files that add use-case-specific packages and settings on top of base.nix.
You pick one when running nixos-rebuild switch by choosing pentest or gaming.

profiles/gaming.nix
  Adds Steam, Lutris, Heroic (Epic/GOG launcher), MangoHud (in-game overlay),
  GameMode (CPU/GPU optimisation daemon), ProtonUp-Qt (Proton version manager),
  and PrismLauncher (Minecraft). Sets GAME_DEBUGGER=gamemoderun so gamemode
  is used automatically, and PROTON_ENABLE_NVAPI=1 for NVIDIA DLSS support.

profiles/pentest.nix
  Adds an extensive penetration testing toolkit. Python with a full set of
  security libraries (impacket, bloodhound-py, lsassy, pypykatz, etc.).
  Network tools (nmap, wireshark, masscan, rustscan, netexec, tcpdump).
  Web tools (burpsuite, zaproxy, nikto, gobuster, ffuf, dirsearch, wpscan).
  Password tools (hashcat, john, thc-hydra, medusa, ncrack, crowbar).
  AD/Windows tools (bloodhound, certipy, kerbrute, responder, evil-winrm).
  Wireless tools (aircrack-ng, wifite2, hcxtools, kismet).
  Exploitation (metasploit, sqlmap, exploitdb, radare2, gdb, binwalk).
  Tunneling and pivoting (chisel, ligolo-ng, proxychains, socat, ptunnel).
  Neo4j is configured (but not enabled by default) for BloodHound graph data.
  Samba is configured (but not enabled by default) for SMB shares.
  ProxyChains is configured with a strict chain to localhost:9050 (tor/proxy).
  WiFi power save is disabled for better capture reliability.

 user.nix
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Managed by home-manager. Everything that lives inside your home directory and
is user-specific. Runs as your user, not root. Applied during nixos-rebuild
switch as part of the home-manager activation.

NEOVIM
  init.lua is symlinked from rice/neovim/init.lua. A set of LSP, completion,
  and treesitter plugins are declared here and managed by Nix so they are
  always present and at consistent versions.

THEMING
  GTK theme is set to adw-gtk3-dark with dark color scheme preference via
  dconf. Cursor theme is configured. This ensures GTK apps follow the dark
  theme without any manual configuration.

MATUGEN
  The matugen config directory (rice/matugen/) is symlinked to
  ~/.config/matugen/. Matugen is the wallpaper-to-theme engine. It reads
  a wallpaper image, generates a full Material You color palette from it,
  and then uses the templates in rice/matugen/templates/ to regenerate
  color config files for every application. See the matugen section below
  for full details.

CAVA
  The base cava config (rice/cava/config_base) is symlinked to
  ~/.config/cava/config_base. Cava is an audio visualizer. Colors are
  regenerated by matugen separately.

ROFI
  All three rofi config files (config.rasi, theme.rasi, powermenu-theme.rasi)
  are symlinked from rice/rofi/. Rofi is used as the application launcher
  and power menu.

SWAYNC
  Config and stylesheet symlinked from rice/swaync/. Swaync is the
  notification daemon with a slide-out notification center.

WAYBAR
  Configured inline in user.nix with a full style declaration. Waybar is
  the fallback status bar. In normal use the quickshell topbar takes over,
  but waybar is available as a backup.

HYPRLAND (home-manager module)
  The home-manager hyprland module is enabled with xwayland and systemd
  integration. The extraConfig block defines what the generated hyprland.conf
  will source. It sources these files in order:
    colors.conf         — border and accent colors from matugen
    monitors.conf       — monitor layout from settings.json
    env.conf            — environment variables for GPU etc
    autostart.conf      — programs launched when Hyprland starts
    variables.conf      — static Hyprland variables (gaps, borders, etc)
    settings.conf       — input sensitivity, keyboard layout etc
    rules.conf          — window rules (floats, sizes, workspaces, opacity)
    keybindings.conf    — all keyboard shortcuts

  The package and portalPackage are set to null because Hyprland is installed
  system-wide in base.nix and home-manager should not try to install its own.

HYPRLOCK
  Screen lock configured with a dark overlay, blurred background using the
  wallpaper from wallpaperDir, a large clock, date, and a password input field
  styled in the green accent color.

HYPRIDLE
  Idle daemon configured to lock the session before sleep. The listener list
  is empty by default, meaning the screen does not auto-lock on idle unless
  you add timeout listeners. Lock happens on suspend.

ACTIVATION HOOK (setupRice)
  This is the most important part of user.nix for portability. It runs every
  time nixos-rebuild switch completes, after all files have been deployed.

  What it does in order:
  1. Creates ~/.config/hypr/config/ directory if it does not exist.
  2. Initializes colors.conf with default green borders if it does not exist.
     This only happens once on first install, matugen overwrites it later.
  3. Makes all scripts in ~/.config/hypr/scripts/ executable.
  4. Ensures settings.json exists (creates empty {} if missing).
  5. Writes to settings.json using jq:
       - inputSensitivity is ALWAYS written from config.nix (overwrite)
       - All other keys use //= (only written if the key is missing):
           wallpaperDir    — points to ~/hacknix/wallpapers
           uiScale         — 1
           openGuideAtStartup — false
           topbarHelpIcon  — false
           language        — "" (system default)
           kbOptions       — "grp:alt_shift_toggle"
           workspaceCount  — 8
  6. Runs settings_watcher.sh --compile to generate all Hyprland config files
     from the templates and the now-populated settings.json.
  7. Copies all scripts from rice/scripts/ to ~/.local/bin/ and makes them
     executable so they are available on PATH.

  The result: on a first install everything works with no manual setup.
  On every subsequent rebuild your existing settings are preserved and only
  inputSensitivity is updated if you changed it in config.nix.

SCRIPTS IN ~/.local/bin/
  All scripts from rice/scripts/ are copied here. This includes utility
  scripts for wallpaper management, screenshots, toggling various features,
  power management menus, and more. See the rice/scripts/ section below.

Everything Hyprland related. Split into config (static files), templates
(files that get generated at runtime), and scripts (programs that run).

── rice/hypr/config/ ───────────────────────────────────────────────────────────

Static Hyprland configuration files. Two of these are deployed as read-only
symlinks by home-manager. The rest are reference copies and are NOT deployed
directly — they are the output location where settings_watcher.sh writes
generated files when run locally.

  rules.conf
    Window rules. Controls which windows open floating, at what size, on which
    workspace, with what opacity. Deployed as a symlink to
    ~/.config/hypr/config/rules.conf. Changes here apply on next rebuild.

  variables.conf
    Static Hyprland variables. Gap sizes, border widths, animation speeds,
    blur settings, rounding. Deployed as a symlink to
    ~/.config/hypr/config/variables.conf. Changes here apply on next rebuild.

  settings.conf, monitors.conf, env.conf, autostart.conf, keybindings.conf
    These are NOT deployed by home-manager. They are generated at runtime by
    settings_watcher.sh from the templates and settings.json. The copies in
    rice/hypr/config/ are what they look like on the PC and serve as reference.
    On any device the real files live in ~/.config/hypr/config/.

── rice/hypr/templates/ ────────────────────────────────────────────────────────

Template files that settings_watcher.sh uses to generate the actual Hyprland
config files. Deployed as read-only symlinks to ~/.config/hypr/templates/.
Placeholders in double curly braces get replaced with values from settings.json.

  settings.conf.template
    Template for input settings. Placeholders:
      {{KB_LAYOUT}}         — keyboard layout (e.g. "us")
      {{KB_OPTIONS}}        — keyboard options (e.g. "grp:alt_shift_toggle")
      {{INPUT_SENSITIVITY}} — mouse/touchpad sensitivity from config.nix
    Also contains the device block matching .*touchpad.* for laptops.

  monitors.conf.template
    Just a header comment. settings_watcher.sh appends one monitor line per
    entry in settings.json's monitors array, in the format:
      monitor = NAME, WxH@RATE, XxY, SCALE
    If no monitors are configured, only the fallback line is written:
      monitor = , preferred, auto, 1
    This fallback works on any display without any setup.

  env.conf.template
    Environment variables for the session. Placeholders:
      {{XDG_PICTURES_DIR}}  — path to Pictures folder
      {{XDG_VIDEOS_DIR}}    — path to Videos folder
      {{WALLPAPER_DIR}}     — wallpaper directory from settings.json
      {{SCRIPT_DIR}}        — path to ~/.config/hypr/scripts/
      {{HARDWARE_ENV}}      — GPU-specific env vars from settings.json
    The hardware env vars set things like GBM_BACKEND and
    __GLX_VENDOR_LIBRARY_NAME for NVIDIA, or LIBVA_DRIVER_NAME for AMD.

  autostart.conf.template
    Programs launched when Hyprland starts. Contains static entries plus
    any dynamic entries from settings.json's startup array. Always includes:
      - init-wallpaper (sets wallpaper and runs matugen)
      - hypridle (idle/lock daemon)
      - playerctld (media player daemon)
      - wl-clip-persist (keeps clipboard contents after app closes)
      - cliphist (clipboard history)
      - swaync (notification daemon)
      - waybar (status bar, usually hidden behind quickshell topbar)
      - settings_watcher.sh (watches settings.json for changes)
      - quickshell (the main topbar UI)

  keybinds.conf.template
    All keyboard shortcuts. Contains the static keybinds (window management,
    workspace switching, launching apps, toggling features) plus dynamic
    entries from settings.json's keybinds array.

── rice/hypr/scripts/ ──────────────────────────────────────────────────────────

Runtime scripts that Hyprland and the topbar call. Deployed as read-only
symlinks to ~/.config/hypr/scripts/.

  settings_watcher.sh
    The most critical runtime script. It has two modes:

    --compile mode (run once at activation hook time):
      Reads settings.json and generates all five config files:
        settings.conf, env.conf, keybindings.conf, autostart.conf, monitors.conf
      Compares hashes of old vs new files. Only triggers hyprctl reload if
      something actually changed, and distinguishes monitor changes (which
      cause a full reload) from non-monitor changes (which do a quieter reload).

    daemon mode (run at Hyprland startup, stays running):
      Uses inotifywait to watch settings.json for any write. When it changes,
      calls compile_settings again. This is how changes made through the
      settings UI (topbar popups) apply immediately without restarting Hyprland.
      Also watches the weather .env file and refreshes weather cache when it
      changes.

  settings_watcher.sh is the bridge between the UI and the config files.
  The topbar writes to settings.json, the watcher detects that and regenerates
  everything, hyprctl reload picks up the changes. Live, no restart needed.

  reload.sh
    Manually triggers a hyprctl reload. Useful after making direct edits.

  screenshot.sh
    Takes a screenshot using grimblast. Supports region selection.

  qs_manager.sh
    Controls quickshell windows. Used by keybinds to open/close/toggle
    the various popups (calendar, monitor settings, volume, etc.).

  exit.sh
    Handles Hyprland exit/logout cleanly via UWSM.

  lock.sh
    Triggers hyprlock for screen locking.

  caching.sh
    Cache management helpers used by quickshell.

  volume_listener.sh
    Watches PipeWire/PulseAudio for volume changes and sends updates
    to quickshell so the volume indicator stays current.

  workspaces.sh
    Outputs workspace info in a format quickshell can display.
    Reads workspaceCount from settings.json to know how many to show.

  quickshell/ (directory)
    The entire topbar UI written in QML using quickshell. See the
    quickshell section below for full details.

── rice/hypr/scripts/quickshell/ ───────────────────────────────────────────────

The desktop shell UI. Written in QML and run by quickshell. This is the
topbar, all the popup panels, and the notification system.

  Shell.qml
    Entry point for quickshell. Defines the top-level shell structure and
    loads all other components.

  TopBar.qml
    The main topbar at the top of the screen. Shows workspace indicators,
    active window title, clock, system tray area, and buttons that open
    the various popup panels. Reads from settings.json to know which
    optional icons to show.

  Main.qml
    Core logic hub. Reads and watches settings.json. Coordinates between
    all the popup components.

  Config.qml
    Defines shared path constants used throughout the QML codebase.
    Things like the hypr config dir path, cache dir, settings.json path.

  Scaler.qml
    Responsive scaling logic. Reads the uiScale value from settings.json
    and provides a helper function s() used by all other components to
    scale pixel values. This is how the UI adapts to different display
    sizes and densities.

  MatugenColors.qml
    Reads the matugen-generated color JSON from /tmp/qs_colors.json and
    exposes the color palette to all QML components. This is how the entire
    UI recolors itself when you change the wallpaper.

  monitors/MonitorPopup.qml
    The monitor configuration popup. On open it runs hyprctl monitors -j
    to get the current connected displays, shows them in a drag-and-drop
    layout editor, lets you change resolution and refresh rate from a list,
    set scale, and designate the primary monitor. On apply it writes the
    monitor array to settings.json which triggers settings_watcher.sh to
    regenerate monitors.conf and do a hyprctl reload.

  settings/SettingsPopup.qml
    General settings panel. Controls UI scale, wallpaper directory,
    workspace count, keyboard layout, and other preferences. Writes
    directly to settings.json.

  wallpaper/WallpaperPicker.qml
    Wallpaper picker. Shows thumbnails of images from the wallpaperDir.
    On selection runs matugen to regenerate all theme colors from the
    new wallpaper and sets it as the background via awww.

  volume/VolumePopup.qml
    Volume control popup. Shows current volume level, mute state, and
    lets you adjust volume for different audio sinks.

  music/MusicPopup.qml
    Media player popup. Shows currently playing track info, album art,
    playback controls. Uses playerctl to talk to any MPRIS media player.

  network/NetworkPopup.qml
    Network panel. WiFi list, Bluetooth devices, ethernet status.
    Includes connect/disconnect sounds.

  battery/BatteryPopup.qml
    Battery status popup. Shows charge level, charging state, time
    remaining estimates.

  calendar/CalendarPopup.qml
    Calendar and weather popup. Shows a monthly calendar view with the
    ability to add diary entries. Also shows weather from an API if
    a weather API key is configured in the .env file.

  clipboard/ClipboardManager.qml
    Clipboard history viewer. Shows recent clipboard entries from cliphist
    and lets you paste any of them.

  applauncher/appLauncher.qml
    Application launcher. Alternative to rofi, integrated in the topbar.

  focustime/FocusTimePopup.qml
    Focus time / pomodoro tracker. Tracks focused work sessions.

  notifications/NotificationPopups.qml
    Notification display. Shows incoming notifications as popups.

  quickactions/
    Small utility widgets: a draw-on-screen tool, system resource usage
    display, and a timer.

  guide/GuidePopup.qml
    An interactive guide showing what each popup does with preview images.
    Shown on first startup (controlled by openGuideAtStartup in settings.json).

  updater/UpdaterPopup.qml
    System update helper.

  stewart/stewart.qml
    An AI assistant widget.

  watchers/
    Shell scripts that feed live data to quickshell components via stdout.
    Each has a fetch variant (gets current state once) and a wait variant
    (blocks until state changes, used for inotifywait-style streaming).
    Covers audio, battery, Bluetooth, keyboard, network, system stats.

  WindowRegistry.js
    JavaScript module that tracks which popup windows are currently open
    so the shell can manage them centrally.

The theming engine. Matugen takes a wallpaper image and derives a complete
Material You color palette from it. It then fills in the templates below
and writes the output files so every application matches the wallpaper colors.

  config.toml
    Tells matugen where to write each generated file and which template to use.
    This is the file that maps each template to its output path.

  templates/hyprland.conf.template
    Generates ~/.config/hypr/colors.conf. Defines the $active_border and
    $inactive_border CSS color variables that Hyprland uses for window borders.
    This is what makes your window borders match your wallpaper.

  templates/kitty-colors.conf.template
    Generates /tmp/kitty-matugen-colors.conf. All 16 terminal colors
    (black, red, green, etc.) plus background and foreground, derived from
    the wallpaper palette. Kitty includes this file so the terminal colors
    match the wallpaper.

  templates/gtk.css.template
    Generates the GTK color CSS so GTK application UI elements like buttons
    and highlights follow the wallpaper palette.

  templates/qs_colors.json.template
    Generates /tmp/qs_colors.json which MatugenColors.qml reads to give
    the entire quickshell UI (topbar, all popups) wallpaper-derived colors.

  templates/nvim-colors.lua.template
    Generates ~/.config/nvim/matugen_colors.lua so neovim's color scheme
    follows the wallpaper.

  templates/cava-colors.ini.template
    Generates cava bar colors from the wallpaper palette.

  templates/discord.css.template
    CSS for a Discord theme that follows the wallpaper palette (applied
    via a Discord CSS injector).

  templates/swayosd.css.template
    Colors for SwayOSD (the on-screen display for volume/brightness changes).

  templates/qtct.conf.template and qt-style.qss.template
    Qt application theming to match the palette.

When does matugen run?
  It runs when init-wallpaper.sh executes at Hyprland startup, and again
  whenever you pick a new wallpaper through the wallpaper picker. After it
  runs, all applications that read their color files update. Hyprland reads
  the new colors.conf on next reload.

 ~/.config/hypr/settings.json  (RUNTIME STATE — not in the flake)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

This file lives outside the flake in your home directory. It is the per-device
state store. The flake writes defaults into it on first install and then never
overwrites existing values (except inputSensitivity which always comes from
config.nix). Everything else in this file you control via the settings UI.

Fields:
  inputSensitivity    — always written from config.nix on rebuild
  monitors            — array of monitor configs, written by MonitorPopup
  wallpaperDir        — path to wallpaper folder, written by settings UI
  uiScale             — UI scaling factor for quickshell, written by settings UI
  openGuideAtStartup  — whether to show the guide on first launch
  topbarHelpIcon      — whether to show help icon in topbar
  language            — keyboard layout language code
  kbOptions           — keyboard options string (xkb options)
  workspaceCount      — how many workspaces to show in topbar
  hardwareEnvs        — GPU env vars, written by load_info.sh
  startup             — extra autostart commands (optional)
  keybinds            — extra keybinds (optional)

This file persists across rebuilds on the same device. On a different device
it starts fresh and gets populated by the activation hook defaults, then by
whatever you configure through the UI.

Wallpaper images shipped with the flake. On first install wallpaperDir defaults
to ~/hacknix/wallpapers so the wallpaper picker and init-wallpaper work
immediately without any configuration. Add your own images here or point
wallpaperDir somewhere else through the settings UI.

 HOW EVERYTHING CONNECTS — THE FULL DATA FLOW
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

On nixos-rebuild switch:

  1. Nix reads flake.nix, imports config.nix
  2. mkHost passes hardware values to base.nix and user.nix via specialArgs
  3. base.nix configures the system (boot, kernel, services, packages)
  4. user.nix deploys:
       - Symlinks: rules.conf, variables.conf, templates/, scripts/,
                   matugen/, rofi/, swaync/, neovim init.lua, cava config
       - Inline configs: hyprlock, hypridle, waybar, dconf GTK theme
       - Activation hook: writes settings.json defaults, compiles all
                          generated configs, copies scripts to ~/.local/bin/
  5. Generated configs now exist in ~/.config/hypr/config/ with correct values

On Hyprland startup:

  6. hyprland.conf (managed by home-manager) sources all eight config files
  7. autostart.conf launches: init-wallpaper, hypridle, playerctld,
     wl-clip-persist, cliphist, swaync, waybar, settings_watcher, quickshell
  8. init-wallpaper.sh sets the wallpaper via awww and runs matugen
  9. matugen reads the wallpaper, generates colors, writes to:
       ~/.config/hypr/colors.conf (border colors)
       /tmp/kitty-matugen-colors.conf (terminal colors)
       /tmp/qs_colors.json (topbar UI colors)
       ~/.config/nvim/matugen_colors.lua (neovim colors)
       and more
  10. settings_watcher.sh starts watching settings.json for changes
  11. quickshell starts and reads settings.json and /tmp/qs_colors.json

When you change something in the UI (e.g. monitor resolution):

  12. MonitorPopup writes updated monitors array to settings.json
  13. inotifywait in settings_watcher.sh detects the write
  14. settings_watcher.sh calls compile_settings()
  15. monitors.conf is regenerated from the new monitors array
  16. Hash comparison detects monitors.conf changed
  17. hyprctl reload is triggered
  18. Hyprland re-reads monitors.conf and applies the new resolution
  19. The change is now saved in settings.json and will persist across rebuilds

When you change wallpaper:

  20. WallpaperPicker.qml calls matugen_reload.sh with the new image
  21. awww sets the new wallpaper as background
  22. matugen regenerates all color files
  23. MatugenColors.qml in quickshell detects /tmp/qs_colors.json changed
  24. Topbar and all popups recolor to match the new wallpaper
  25. Hyprland reloads colors.conf so window borders update
  26. Kitty terminal reloads its color file

When you change inputSensitivity in config.nix and rebuild:

  27. Activation hook writes the new value to settings.json
  28. settings_watcher.sh --compile regenerates settings.conf
  29. Hyprland reads the new sensitivity on next reload or restart

 FIRST TIME SETUP ON A NEW DEVICE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  1. Install NixOS on the machine (standard installation)
  2. Clone this repo to ~/hacknix
  3. Run ./load_info.sh from inside ~/hacknix
     — Detects CPU, GPU, input device, writes config.nix
     — Creates ~/.config/hypr/settings.json with hardwareEnvs
     — Review the detected values, confirm, done
  4. Copy hardware-configuration.nix from /etc/nixos/ into ~/hacknix/
     (the installer generates this for your specific hardware)
  5. Run: sudo nixos-rebuild switch --flake ~/hacknix#gaming
     (or #pentest depending on what you want)
  6. Log in — Hyprland starts, rice is fully working
  7. Open the monitor popup and set your display resolution once
     — This persists forever, survives every future rebuild

 WHAT SURVIVES A REBUILD vs WHAT RESETS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

SURVIVES (persists in settings.json or ~/.config/):
  - Monitor layout and resolution
  - Wallpaper directory and current wallpaper
  - UI scale
  - Theme colors (matugen output files)
  - Workspace count
  - Keyboard layout and options
  - Any custom keybinds added via UI
  - Any custom startup commands added via UI
  - Clipboard history
  - Shell history

UPDATED ON REBUILD (from config.nix):
  - inputSensitivity (mouse/touchpad speed)
  - GPU environment variables (via load_info.sh → settings.json)

RESET ONLY ON FIRST INSTALL (initialized from flake defaults):
  - wallpaperDir (set to ~/hacknix/wallpapers)
  - uiScale (set to 1)
  - workspaceCount (set to 8)
  - kbOptions (set to grp:alt_shift_toggle)
  - language (set to empty, uses system default)
  - openGuideAtStartup (set to false)

ALWAYS FROM THE FLAKE (symlinks, reset on every rebuild if you edit the file):
  - Window rules (rules.conf)
  - Hyprland variables like gaps and borders (variables.conf)
  - Keybind templates (keybinds.conf.template)
  - All scripts in ~/.config/hypr/scripts/
  - All scripts in ~/.local/bin/
  - Neovim config
  - Rofi themes
  - Swaync config
  - Matugen templates
  - Plymouth boot theme
